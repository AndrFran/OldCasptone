RACE CONDITION PREVENTION (CRITICAL)
================================================================================

Verified: Two simultaneous requests for the last unit don't create two orders.

Algorithm:
1. Thread 1: BEGIN TRANSACTION (SERIALIZABLE)
2. Thread 1: SELECT products WHERE id=2 FOR UPDATE (acquires lock)
3. Thread 2: BEGIN TRANSACTION (SERIALIZABLE)
4. Thread 2: SELECT products WHERE id=2 FOR UPDATE (WAITS for lock)
5. Thread 1: Check stock >= 1? YES → Decrement stock to 0 → COMMIT (lock released)
6. Thread 2: SELECT products WHERE id=2 FOR UPDATE (lock acquired)
7. Thread 2: Check stock >= 1? NO → ROLLBACK with OutOfStockError (400/409)

Result: Only 1 order created, no overselling ✅
